Skills de Claude Code: qué son y cómo crear una

Instrucciones que Claude carga solo cuando hacen falta. Dónde se guardan, qué lleva la cabecera, un ejemplo oficial para copiar y cómo distinguirlas de CLAUDE.md y de los subagentes.

Qué es una skill

Una skill es un archivo SKILL.md con instrucciones que Claude Code usa cuando encajan con lo que le pides, o que tú llamas directamente escribiendo /nombre-de-la-skill. Según la documentación oficial, el cuerpo de una skill solo se carga cuando se usa, así que puedes guardar material largo de referencia sin gastar contexto hasta que haga falta.

Si buscas skills ya hechas, mira las mejores skills de Claude. Esta guía es para crear la tuya.

Dónde se guardan

~/.claude/skills/<nombre>/SKILL.mdPersonal: sirve en todos tus proyectos.
.claude/skills/<nombre>/SKILL.mdDe proyecto: se sube al repositorio para compartirla.

También existen skills de organización (las gestiona un administrador) y las que vienen dentro de un plugin, que se llaman como /plugin:skill. Si una skill personal y una de proyecto tienen el mismo nombre, gana la personal.

Ejemplo oficial para copiar

Una skill que resume tus cambios

Guarda esto en ~/.claude/skills/summarize-changes/SKILL.md. Después pregúntale a Claude «¿qué he cambiado?» o escribe /summarize-changes.

--- name: summarize-changes description: Summarizes uncommitted changes and flags risks. Use when the user asks what changed or wants a commit message. allowed-tools: Bash(git diff *) Bash(git status *) --- ## Current changes !`git diff HEAD` ## Instructions Summarize the changes above in two or three bullet points, then list any risks, such as missing error handling or hardcoded values. If the diff is empty, say there are no uncommitted changes.

La línea que empieza por ! ejecuta un comando y mete su resultado en la skill antes de que Claude la lea. Es el ejemplo de la documentación; el texto va en inglés porque así lo escribe Anthropic, pero puedes escribir el tuyo en español.

Los campos de la cabecera

Todos son opcionales, pero la documentación recomienda poner description:

nameEl nombre del comando. Si no lo pones, usa el de la carpeta.
descriptionQué hace y cuándo usarla. Claude lo lee para decidir si la carga.
disable-model-invocationCon true, Claude no la carga solo; solo la llamas tú.
user-invocableCon false, no sale en el menú de /; solo la usa Claude.
allowed-toolsHerramientas que se ejecutan sin pedirte permiso mientras dura esa petición.

Skill, CLAUDE.md o subagente

  • CLAUDE.md: datos y reglas que quieres siempre presentes, en cada sesión. Mira cómo escribirlo.
  • Skill: procedimientos y material de consulta que se cargan cuando hacen falta.
  • Subagente: un asistente con su propio contexto. Mira subagentes. Una skill con context: fork se ejecuta dentro de uno.
Lo honesto

Ojo con las que instalas

Una skill son instrucciones que Claude seguirá, y puede ejecutar comandos. Antes de copiar una de internet, léela entera, sobre todo las líneas con ! y el campo allowed-tools. Para fijar reglas que se cumplan siempre, un hook es más fiable que una skill.

Preguntas frecuentes

¿Qué es una skill de Claude Code?

Un archivo SKILL.md con instrucciones que Claude carga cuando encajan con tu petición, o que tú llamas escribiendo /nombre. Su contenido solo entra en el contexto cuando se usa.

¿Dónde se guardan las skills?

En ~/.claude/skills/nombre/SKILL.md para todos tus proyectos o en .claude/skills/nombre/SKILL.md para un proyecto concreto, que se puede compartir con git.

¿Qué campos son obligatorios?

Ninguno es obligatorio, pero la documentación recomienda description, porque Claude la usa para decidir cuándo cargar la skill.

¿Cuál es la diferencia entre una skill y CLAUDE.md?

CLAUDE.md carga siempre en cada sesión. Una skill solo carga cuando se usa, así que sirve para procedimientos largos o material de consulta.

¿Cómo evito que Claude use una skill por su cuenta?

Poniendo disable-model-invocation: true en la cabecera. Entonces solo se ejecuta cuando la llamas tú con /nombre.
